# CafeChalao: backend API

CafeChalao is a white-label app for cafés and restaurants in India. It covers:

- Online ordering (delivery and takeaway), plus dine-in from a table QR.
- POS billing, the captain (waiter) app, the kitchen display and riders.
- Menu, recipes, stock and purchases.
- Staff and salaries.
- Offers, customers and reports.
- A Control Panel to onboard new cafés.

This repository is the **backend**: a Laravel 11 (PHP 8.2+) API on MySQL. One deployment serves many cafés, and each café's data is kept separate. The website and staff apps that use it are in the frontend repository: **[cafechalao](https://github.com/nayanjyotigogoi/cafechalao)**.

## Run it locally

**With WAMP or any local MySQL:** create a database `cafechalao`, then:

```bash
composer install
cp .env.example .env          # set DB_CONNECTION=mysql and the DB_* values
php artisan key:generate
php artisan migrate
php artisan serve --port=8000
```

**With Docker:**

```bash
docker compose up --build
```

This gives MySQL on port 3307 and the API on http://localhost:8000.

### Demo cafés (optional)

`php artisan migrate:fresh --seed` loads four demo cafés with menus, orders and staff. Their data is generated by the frontend, so:

1. In the frontend repository, run `npm run seed:export`.
2. Copy the `seed-data/` folder it creates into this repository's `database/seed-data/`, or set `SEED_DATA_PATH` to point at it.

The backend tests use the same data.

To create a real café instead, use the Control Panel (`/control` on the website). The new owner signs in with employee ID **E001** and sets their own PIN.

## Settings that matter

| `.env` | Meaning |
| --- | --- |
| `APP_URL` | This API's public address. Uploaded images are linked from it. |
| `CORS_ALLOWED_ORIGINS` | Websites allowed to call the API, comma separated (`*` locally) |
| `DEMO_MODE`, `DEMO_OTP` | Demo: sign-in codes are always `DEMO_OTP` and shown on screen. Set `DEMO_MODE=false` once SMS is connected. |
| `GOOGLE_CLIENT_ID` | Optional "Continue with Google" for guests |
| `RAZORPAY_*`, `CASHFREE_*`, `PHONEPE_*` | Optional gateways. Without them, each café's own UPI QR is used. |

## Uploaded images

Menu photos, logos, UPI QR codes, bill photos and selfies are saved straight into **`public/storage`** and served from there. No `storage:link` is needed.

`php artisan media:to-public` moves images from the old `storage/app/public` location, and with `--from-url=<old address>` points saved image links at the current `APP_URL`.

## Production (tohfaah.online)

The production setup in `docker-compose.prod.yml` runs three things:

- **MySQL**, with a volume for its data.
- **This API**, behind Apache.
- **Caddy**, which gets HTTPS certificates for both **tohfaah.online** (this API) and **tohfaah.com** (the website from the frontend repository, on the same server; it joins this setup's private `cafechalao` network).

### Steps

1. **Server:** a Linux VPS with 2 GB RAM and Docker installed (`curl -fsSL https://get.docker.com | sh`).
2. **DNS:** point the `A` records of `tohfaah.online`, `www.tohfaah.online`, `tohfaah.com` and `www.tohfaah.com` to the server's IP.
3. **Get this repository and fill in the settings:**

   ```bash
   git clone https://github.com/nayanjyotigogoi/CC-BEND.git && cd CC-BEND
   cp .env.production.example .env.production
   ```

   Then fill in `DB_PASSWORD` and `APP_KEY` in `.env.production`. To get a key, run:

   ```bash
   docker compose -f docker-compose.prod.yml --env-file .env.production run --rm --no-deps api php artisan key:generate --show
   ```

4. **Start the backend:**

   ```bash
   docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
   ```

   Tables are created and new migrations are applied each time the API starts.

5. **Start the website:** clone the frontend repository and run `docker compose -f docker-compose.prod.yml up -d --build` there.

### Moving an existing café's data to the server

1. **Export the local database:**

   ```bash
   mysqldump -u root cafechalao > cafechalao.sql
   ```

2. **Import it on the server:**

   ```bash
   docker compose -f docker-compose.prod.yml exec -T db sh -c 'mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"' < cafechalao.sql
   ```

3. **Copy the images:** copy your local `public/storage` folder to the server as `./storage-upload`, then:

   ```bash
   docker compose -f docker-compose.prod.yml cp storage-upload/. api:/var/www/html/public/storage/
   ```

4. **Fix the image links:**

   ```bash
   docker compose -f docker-compose.prod.yml exec api php artisan media:to-public --from-url=http://localhost:8000
   ```

5. **Reprint the table QR codes** from Admin → Tables & QR, so they open the live site.

### Updating

```bash
git pull
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

## How it is built

| Concern | Where |
| --- | --- |
| Tables and columns | `app/Core/Schema.php`: migrations, type casting and seeding all read it |
| Endpoints, login and permissions per route | Declared in each module with `Api::get/post/…`; `app/Core/Api.php` handles café, login, permission, idempotency and the `{ data }` / error format |
| Café scope and soft delete | `app/Core/Db.php` |
| Roles, permissions, business-type presets, limits | `config/cafechalao.php` |
| GST and bill pricing | `app/Shared/Pricing.php` + `Orders::buildQuote()` |
| KPIs | `app/Shared/Kpi.php` |
| Approvals (manager PIN) | `app/Core/Approvals.php` |
| Uploads | `app/Shared/Media.php` |
| New café defaults (owner E001, invoice prefix from the café name) | `app/Shared/CafeFactory.php` |

Modules (`app/Modules`): Auth, Outlet, Menu, Orders, Billing, DineIn, Customers, Marketing, Inventory, Expenses, Staff, Delivery, Reports, Control.

Staff sign in with **employee ID + PIN** (`POST /auth/pin`). There is no public list of staff. A user without a PIN confirms a code sent to their mobile and chooses one (`/auth/pin/code`, `/auth/pin/setup`).

## Tests

```bash
php artisan test
```

The 30 feature and unit tests cover:

- GST and pricing.
- Café isolation.
- Delivery and dine-in flows, and UPI QR confirmation.
- Double taps, out-of-stock at checkout, stale edits and day close.
- Approvals, back-office access and reports.
- Staff sign-in.

They need `database/seed-data` (see above).
